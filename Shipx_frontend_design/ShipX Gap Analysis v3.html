Scheduled-job notifications ignore locale

Half-wired

The locale feature is fully built — columns, write paths, ZH templates, and correct forwarding in the tracking service. But the scheduled jobs never forward it, so every automated reminder still goes out in English regardless of the recipient's setting.

Four scheduled jobs don't select or pass locale
MediumBackend

Migration 026 added locale to both customer and tenant_user, and the SQS consumers already pick the ZH template when locale == 'zh'. But the scheduled jobs call enqueue_notification(...) with no locale arg, and their recipient-lookup queries don't even SELECT the locale column. Result: a Chinese-preference customer or staffer receives English for storage reminders, release-expiry notices, dispute escalations, and SLA alerts. This is the exact downstream gap flagged when the locale write path was added — fixed for tracking, missed for the scheduled tier.

Customer-facingstorage_reminders.py, release_expiry.py — _get_customer_contact selects only c.id, u.email, u.phone_number (no c.locale)
Staff-facingdispute_escalation.py, sla_check.py — select tu.email, tu.phone_number (no tu.locale)
FixAdd the locale column to each lookup query and pass locale= into every enqueue_notification call. Where a job notifies both customer and staff, use each recipient's own locale.
EffortSmall — 4 files, query + call-site each. Added as Task 4 in the prompts file.
